# 《单骑·过五关》3D 剧情 Demo 方案 v0.1

> 工作名：单骑 / 过五关  
> 题材：《三国演义》第二十七回「美髯公千里走单骑 汉寿侯五关斩六将」  
> 形态：第三人称 3D 动作剧情，单机，30 分钟左右一周目  
> 引擎：Unity 2022.3.62f3c1（China Edition，Apple Silicon 原生）+ URP 14  
> 目标平台：macOS / Windows，1080p / 60fps；WebGL 可选

---

## 1. 参考方法摘要

来源：Sac（@Saccc_c）《手把手教你用 Opus 5.5 / Astra + Tripo 制作 3D 游戏》，16 天完成《小王子》可探索 3D 游戏。

### 1.1 五段流水线

| 环节 | 工具 | 产出 | 验收物 |
| --- | --- | --- | --- |
| 需求 | Fable 5.1 | PRD：场景、人物、剧情线 | 可执行的场景/角色清单 |
| 概念 | Image 2.5 | 场景多视角参考图、人物 T-pose 四视图 | 画风、配色、布局定死 |
| 资产 | Tripo（H3.1 / Smart Mesh P2.0） | 独立道具、可控面数人物模型 | 白模网格、四边面拓扑 |
| 实现 | Opus 5.5 + Blender CLI + Unity MCP | 场景复刻、绑骨、动作、核心代码 | 多机位截图对照 |
| 迭代 | Astra + 独立审查 agent | bug 修复、体验优化 | 多机位盲审通过 |

### 1.2 四条可迁移原则

1. **按能力分工，不按工具分工**：图像模型决定「看起来像什么」，3D 生成决定「它是什么」，编码模型决定「怎么动、怎么玩」，独立审查 agent 决定「对不对」。
2. **每个环节都有可判定的验收物**：参考图、四边面拓扑、基础动作测试、多机位盲审。没有验收物就会退化成反复抽卡。
3. **参考图先定死，再拆资产**：先出一张满意的场景总图，再补俯视/斜侧/细节；先做人物四视图，再进 3D。
4. **资产分流**：独特造型、需要细节的走 Tripo；地形、重复结构、需要精确尺寸的在 Blender 里搭。

### 1.3 场景与人物子流程

- 场景：场景图 → AI 在图上圈注「Tripo 生成 / Blender 搭建」→ Tripo 出道具 → Blender 按参考图摆放 → 正/侧/顶多机位截图迭代。
- 人物：T-pose 四视图 → Tripo 多视图 + 四边形拓扑 + Smart Mesh P2.0 → 白模检查 → 贴图 → Auto-Rig Pro 绑骨蒙皮 → Mixamo 动作重定向 → 接触类动作（握持、提物）用 IK 手调。

### 1.4 与小王子项目的差异

小王子是「探索 + 轻交互」，本项目是「动作 + 护送 + 叙事」。资产管线可以照搬，但**战斗手感无法靠生成模型解决**，必须先用灰盒把移动、锁定、攻击、受击、镜头调到能玩，再进入美术生产。这是本方案与原文最大的不同。

## 2. 适配三国的三个判断

1. **以演义为准，不做考古复原**：青龙偃月刀、赤兔马、绿袍赤面长髯都是演义符号，优先辨识度。但**必须排除明清与日式元素**（山文甲、鱼鳞罩甲、天守、鸟居、和服交领），这是 AI 生成最容易跑偏的地方。
2. **不做魂类**：关羽在文本里是碾压式的。核心爽感是「一骑当千」，难度来自**保护车仗**和**敌将决斗的节奏**，不是来自被杂兵磨死。
3. **线性关卡是优势**：五关天然是五个章节、五种场景、五个 Boss，不需要开放世界。预算全部投在「每关一个专属动词」上。

## 3. Demo 定义

### 3.1 一句话

> 你骑赤兔、提青龙偃月刀，护着两辆车仗穿过五个关隘；挡路者皆斩，但车不能停。

### 3.2 体验支柱

| 支柱 | 玩家感受 | 实现手段 |
| --- | --- | --- |
| 一骑当千 | 冲锋撞开人墙，一刀扫倒一片 | 骑战冲锋、多目标横扫、斩将溃敌 |
| 护送的张力 | 杀得正爽，车仗在挨打 | 车仗耐久、分兵 AI、回护冲刺 |
| 章回仪式感 | 像在读一回绣像演义 | 章回标题卡、水墨过场、原文引文 |

### 3.3 一局流程

序章（灞桥挑袍，3 分钟）→ 东岭关 → 洛阳 → 汜水关 → 荥阳 → 黄河渡口 → 尾声（张辽传令）

## 4. 关卡设计

| # | 关卡 | 守将 | 场景 | 专属动词 | 叙事钩子 | 时长 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | 灞桥 | — | 许都郊外、长亭、柳 | 移动/上马/对话教学 | 挂印封金，刀尖挑袍 | 3 min |
| 1 | 东岭关 | 孔秀 | 黄土隘口、单门关城 | 步战决斗教学 | 无文凭被阻，怒而斩之 | 4 min |
| 2 | 洛阳 | 韩福、孟坦 | 官道、箭楼、土墙 | 诱敌 + 箭雨 + 中箭 | 孟坦诈败，韩福暗箭伤左臂 | 6 min |
| 3 | 汜水关 | 卞喜 | 镇国寺（室内）、山门 | 识破鸿门宴 → 室内围攻 | 普净以眼色相告 | 6 min |
| 4 | 荥阳 | 王植 | 馆驿、夜、火场 | 火场护送突围 | 胡班夜半告密 | 6 min |
| 5 | 黄河渡口 | 秦琪 | 河岸、渡船、芦苇 | 骑战冲锋 | 夏侯惇追至，张辽传令 | 7 min |

设计约束：
- 每关一个新动词，不重复堆怪。
- 每关至少一次「车仗受威胁」的时刻，强化护送主题（洛阳箭雨、汜水关被围、荥阳火场）。
- 敌将战不超过 90 秒，失败可立即重试，检查点设在关前。

## 5. 核心玩法

### 5.1 状态

步行 / 骑乘 / 单挑（锁定）三态，一键上下马。骑乘速度高、转向半径大、可冲锋；步战灵活、可格挡。

### 5.2 战斗

- **轻击**：横扫，多目标，低伤害，积累威压。
- **重击**：竖劈，破架势，前摇长。
- **蓄力（拖刀）**：移动中蓄力，命中造成大量伤害并击倒，需把握时机。
- **格挡 / 完美格挡**：按住格挡；命中前 0.2s 内格挡触发硬直与反击窗口。
- **闪避**：短距离，消耗体力。
- **斩将**：敌将架势破且血量 < 30% → 触发处决演出（3 套预设镜头，非 QTE）。
- **威压**：斩杀累积，满值释放范围击退；斩将直接导致周围杂兵溃逃。

### 5.3 护送

车仗有独立耐久，敌军会分兵攻击。关羽有「回护」短冲刺，可快速回防并格挡箭矢。车仗被毁 = 失败重开。

### 5.4 敌人

- 杂兵：刀盾、长矛、弓手三型，包围但不围殴（同屏同时攻击 ≤ 3）。
- 精锐：盾阵阻挡冲锋、弓阵齐射。
- 敌将：独立架势条、招式前摇明显、会格挡与后撤。

### 5.5 叙事

章回标题卡 + 旁白 + 2~4 轮短对话，可跳过。关间用水墨卷轴 + 原文引文过渡。Demo 不做分支结局，只在 2~3 处给「杀 / 放」选择，影响结算称号。

## 6. 美术方向

**「汉末青绿」**：低饱和青绿 + 赭石 + 土黄，布面颗粒，体积雾，低多边形手绘 PBR。

- 色彩：赭石 `#8C5A3C`、青绿 `#2F4F4A`、土黄 `#C9A66B`、血红 `#8A2B22`、雾白 `#D8D2C4`。
- 造型：汉制札甲、盆领、兜鍪、环首刀、卜字戟、漆盾、幅巾；夯土城墙、木构城楼、汉阙、瓦当。
- 人物：7 头身、硬朗块面、不做写实皮肤与面部捕捉；用胡须、头盔、护手规避 AI 模型最弱的脸和手。
- 关羽：绿袍、赤面（风格化）、长髯、青龙偃月刀；剪影优先。
- 镜头：第三人称越肩，战斗 FOV 55°，骑战 65°，斩将切电影机位。

## 7. 资产与管线

### 7.1 预算

| 类别 | 数量 | 来源 | 面数预算 |
| --- | --- | --- | --- |
| 可操作角色 | 1（关羽） | Tripo Smart Mesh + 手工修 | 25k |
| 敌将 | 7（六将 + 夏侯惇） | Tripo Smart Mesh | 15~20k |
| 次要人物 | 4（甘/糜夫人、普净、胡班） | Tripo / 低模 | 8k |
| 士兵 | 3 型 × 2 阵营色 | Tripo + 换色 | 6k |
| 马 | 2（赤兔、普通） | Tripo + 四足绑骨 | 12k |
| 场景模块 | 6 套（关城/官道/寺庙/馆驿/渡口/营帐） | Blender 程序化 + Tripo 地标 | 可见面 < 200k |
| 道具 | 35~45 | Tripo | 1~5k |
| 动画 | 30~40 clip | Mixamo + 手 K | — |

### 7.2 资产分流规则

- **Tripo**：关城楼、寺塔、渡船、车仗、香炉、兵器架、旗帜、独特道具、全部角色。
- **Blender**：地形、道路、城墙模块、植被、远景山、可复用建筑构件。
- **程序化**：雾、雨、火光、旗帜飘动、人群实例化。

### 7.3 可复用提示词（已按三国改写）

场景总图：
> 基于以下设定生成一张「汉末关隘」场景全面貌参考图：主视图 + 俯视图 + 斜侧视图 + 局部细节（城门、箭楼、拒马、旌旗）。风格：低多边形、手绘 PBR、低饱和青绿与赭石、体积雾、布面颗粒。时代为东汉末年：夯土城墙、木构城楼、汉阙。禁止日式天守、鸟居、明清建筑与盔甲、现代元素。

资产拆解：
> 我的技术栈是 Tripo + Blender + Three.js。基于这张场景参考图，分析哪些资产适合 Tripo 单独生成、哪些适合 Blender 程序化搭建。在图上用编号圈注 Tripo 资产，并给出面数与贴图预算。

人物四视图：
> 生成关羽的 T-pose 四视图（正/背/左/右），细节一致：绿袍、赤面、长髯、汉制札甲、青龙偃月刀。7 头身，低多边形风格化，纯色背景，无阴影。

绑骨：
> 使用 Auto-Rig Pro 完成绑骨与蒙皮，骨骼对齐关节。完成后测试抬手、弯腿、转身，修正变形、拉扯与穿模。

动作重定向：
> 将 Mixamo 动作重定向到该角色骨骼，检查肩、肘、腕的轴向与比例差异，修正滑步与穿模。

接触动作：
> 以提供的 Mixamo 动作为基础，用 Auto-Rig Pro 的手臂 IK 调整持刀姿势，修正握持点与刀身角度，避免穿模与脱手。

### 7.4 审查机制

- `tools/shots.mjs`：Playwright 对每关自动截 6 个机位（正/侧/后/俯/近景/战斗瞬间）。
- 独立审查 agent（视觉）对照参考图做盲审，输出差异清单。
- 代码审查 agent 检查性能、状态机、内存泄漏。
- 每关验收清单：可通关、60fps、无穿模、镜头不穿墙、对话可跳过。

## 8. 技术方案

**Unity 2022.3 LTS + URP 14**，Apple Silicon 原生。当前网络只能取到 China Edition 的 2022.3；URP 14、Cinemachine 2.x、Timeline、Animation Rigging 均可用，后续拿到 Unity 6 安装包可整体升级。

| 层 | 选型 |
| --- | --- |
| 渲染 | URP + Shader Graph（手绘风）+ Volume 后处理 + 高度雾 |
| 输入 | Input System |
| 角色 | CharacterController + 自定义攻击判定（Overlap + hitstop） |
| 动画 | Animator + Animation Rigging（手部 IK、持刀）+ Timeline（斩将演出） |
| 镜头 | Cinemachine（越肩、锁定、演出机位） |
| 叙事 | 轻量状态机 + ScriptableObject 关卡数据 |
| 音频 | Unity Audio（后续可换 FMOD） |
| 资产 | FBX → Blender 整理 → Unity；Addressables 分包 |
| 测试 | Unity Test Framework（EditMode / PlayMode）+ 截图 harness |
| 自动化 | Unity MCP（官方 `com.unity.pipeline`，备选 Coplay MCP）+ batchmode CLI |
| 构建 | macOS（Apple Silicon）/ Windows（IL2CPP）；WebGL 可选 |

自动化闭环：

- `-batchmode -quit -executeMethod BuildScript.Build` 一条命令出包；
- PlayMode 截图测试：每关固定 6 机位 + 战斗瞬间，输出 PNG 给视觉审查 agent；
- 编译瘦身：asmdef 拆分、Enter Play Mode Options 关闭域重载。

移植保障：关卡、对话、数值全部走 ScriptableObject + JSON，不写死在场景里。

性能目标：1080p / 60fps，可见三角面 < 200k，同屏士兵 ≤ 40，首屏 < 10s。
